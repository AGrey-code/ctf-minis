The Neighbor Variable

Binary exploitation mini-challenge · beginner · about 5 minutes

Your mission

Below is a simulated terminal connected to a tiny login program. The program's source code is shown too, so you can read exactly how it works. Find input that makes it print the flag, which looks like CTF{...}.

Nothing to install. The terminal is a simulation that runs in your browser.

The source code

// login.c
#include <stdio.h>
#include <string.h>

int main() {
    char buffer[8];        // holds 8 characters
    int  authorized = 0;   // sits right after buffer in memory

    printf("=== Login System v1.0 ===\n");
    printf("Enter your name: ");
    gets(buffer);           // reads input with NO length check

    if (authorized) {
        printf("Welcome, authorized user!\n");
        // ... prints the flag ...
    } else {
        printf("Access denied. (authorized = %d)\n", authorized);
    }
    return 0;
}

gets() copies input into buffer with no limit. In memory, the authorized variable happens to sit immediately after buffer. If your input is longer than 8 characters, the extra characters don't fit, so they spill into whatever comes next.

Stuck?

Hint 1. buffer is declared as 8 characters, but gets() never checks how much you type. What happens if you type more than 8 characters?
Hint 2. In memory, authorized sits right after buffer, with nothing in between. Characters typed past position 8 land directly on top of authorized's bytes.
Hint 3. authorized only needs to become non-zero, not any specific value. Run ./login, and at the "Enter your name" prompt, type a name longer than 8 characters. Watch the memory view to see the overflow happen live.
Last hint: the answer. Only open this if you have tried the earlier hints.

At the terminal prompt, run:

./login

Then, at the "Enter your name:" prompt, type a name of more than 8 characters, for example:

AAAAAAAAAAAAA

The first character past position 8 overwrites a byte of authorized with a non-zero value, so the check if (authorized) passes and the program prints the flag.

Why this worked

This is a classic stack buffer overflow. buffer and authorized are neighbors in memory, and gets() has no idea where buffer is supposed to end. Writing past the end of one variable overwrites whatever comes next. Here that happened to be a security check, which is exactly the kind of bug that real exploits rely on, just usually overwriting something more powerful, like a saved return address.

The fix: use a bounded function like fgets(buffer, sizeof(buffer), stdin) instead of gets(), which was so dangerous it was removed from the C standard entirely.
